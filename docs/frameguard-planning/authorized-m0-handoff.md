### Required technical experiments

Generate controlled self-contained H.264/yuv420p MP4/MOV with AAC where applicable, video-only clips, rational30000/1001 FPS, multiple/default-disposition streams and cover art where supported. Probe actual stored inventory, indexes, rate fields, coded dimensions, rotation and optional metadata. Inventory all streams, choose default-disposition real video then lowest absolute index, choose audio similarly, and exclude attached pictures from real video. Map selected absolute indexes explicitly; alternate tracks remain uninspected.

Validate separate blackdetect and silencedetect passes against known decoded-frame/sample ground truth. FrameGuard defaults are black minimum0.5s/pic_th0.98/pix_th0.10 and silence minimum2s/noise-60dB with collective channels. Test known interior black1–3s and silence1–4s, leading/trailing/all-black/all-silent clips, below/equal/above minimum durations, and active-one-channel versus all-silent audio. Use the fixture recipes and tolerances in acceptance-tests.md, distinguishing PCM oracle from AAC decoded behavior.

Verify native EOF semantics on the actual builds. Current upstream blackdetect source closes trailing black at last picture PTS, not PTS plus final-frame duration; the accepted v0.1 contract reports native evidence with that limitation and possible threshold-edge misses. Do not pad endpoints using average FPS or container duration. Current silence source closes qualifying trailing silence at audio-frame end. Both filters can emit closure during failure/cancellation teardown, so a closing event alone is not successful EOF evidence.

Test common/nonzero/negative starts, unequal A/V offsets, and an explicit MOV/MP4 edit-list fixture. Verify the intended edit-list structure is actually stored, establish decoded frame/sample PTS, and compare raw detector events and shared-origin normalization on floor/newer builds. An offset-only fixture is not edit-list evidence. Preserve raw source timestamps; use one documented common origin, never reset each stream independently, never substitute duration for absolute end. Unknown origin is explicitly source-PTS mode, not invented zero-relative timing. Unknown duration alone need not prevent a valid full decode.

Validate actual filter-attributed log grammar, malformed/finite timestamp behavior and successful versus failing decode/cancellation. Include a controlled simulated early attributable decode error followed by diagnostic-tail rotation, valid closing events and zero return code; sticky decode-error state must still make the result failed/incomplete. Label simulated process/parser observations separately from real native experiments. Require validated -xerror behavior and completion evidence; never claim a zero-exit/no-event pass if errors or authoritative-output loss were observed.

Validate safe self-contained input handling: forced MOV demuxer, file-only protocol restrictions and external data references disabled on the supported builds. Reject manifests/URLs/reference loading rather than allowing FFmpeg to fetch other resources. File-only protocols are not a filesystem sandbox. Use only controlled test resources and denied/monitored network conditions; do not contact external services or upload footage. Remove inherited FFREPORT and disable log colors.

All subprocess calls use argv arrays, shell=false, stdin disabled, bounded execution/output and concurrent pipe drains. Confirm selected mapping, copyts, noautorotate, no-resampling/null-output behavior. No -shortest, seeking, artificial truncation, CFR override, downmix, or user-supplied filter fragments. Test timeout/output flooding/cancellation cleanup with controlled fake children; terminate, then kill after a two-second grace and reap.
